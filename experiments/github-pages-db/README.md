# 制度DB横断検索の非公開試作

**HOLD_NO_MERGE / NO_DEPLOY。** これは検索移植の検証用コードです。
GitHub Pagesの完全な出力でも、公開を許可されたデータセットでもありません。

## 検証すること

- 現行の `lib/database-search.ts` をビルド時にJavaScriptへ変換し、
  同義語、正規化、重み付け、順位付けを再利用する。
- 現行の公開判定関数を使ってサービス別の検索対象を作り、
  条文を構成する各ノードが個別の公開判定も通ることを確認する。
- 全体検索とサービス別検索について、現行画面の処理から別途組み立てた
  基準と、件数・全結果のID・順位・リンク先を比較する。
- 検索用データは全体用とサービス別に分けて生成する。生成先はOSの
  一時ディレクトリに固定し、リポジトリ内やPagesの出力先には置かない。
- 手元またはCIにChromeがある場合、ループバック上の試作をヘッドレスで
  表示して検索結果と画面の横はみ出しを確認する。

## 実行

Node.js 24で、既存リポジトリの依存データを取得したうえで実行する。

```sh
node --import ./experiments/github-pages-db/register.mjs --test tests/github-pages-db-pilot.test.mjs
```

試作だけを生成する場合：

```sh
node --import ./experiments/github-pages-db/register.mjs experiments/github-pages-db/build.mjs
```

通常のNext.jsビルドを済ませた後、39サービスの手引試作と検索試作を
一つの一時ディレクトリにまとめる場合：

```sh
python scripts/build_github_pages_integrated_pilot.py
```

この統合出力は手引と横断検索だけの部分試作で、検索結果などのリンク先には
現行サイトが残ります。公開ファイルの全量や、1 GB制限への正式な適合を
示すものではありません。

テストは終了時に一時出力を消す。手動生成した出力は自動削除されないため、
検証終了後に表示された一時ディレクトリを削除する。

## 公開前に必要な作業

- 全体検索用データには、現行サイトで検索できるQ&Aや通知を含む。
  Q&Aには取込後未レビューのものがあり、通知にも人手確認未実施のものがある。
  一括ダウンロード可能にすることの公開範囲と公開項目は未承認。
- 実際の詳細ページは含まれない。試作画面のリンクは現行Vercelサイトへ遷移する。
  現行の表示や地域区分のグループ表示との同等性も未達。
- 全ページの静的化、公開候補の網羅的な情報漏えい監査、
  法令・原典リンクの照合、Android実機性能・操作、独立受入が未了。
- 生成物の容量は**検索試作だけ**の数値であり、サイト全体の
  GitHub Pages向け最終出力容量ではない。

`noindex` は非公開の保証ではない。CIの成果物や公開ディレクトリへ
このデータをコピーしないこと。
