# GitHub Pages の継続更新（試験公開のみ）

## 目的と現在の制限

GitHub Pages の試験公開を、固定 SHA の毎回の書き換えなしで更新できるようにする。
この変更は **正式公開の自動化ではない**。国の制度資料の現行性・資料単位の公開範囲・独立受入の承認は別途必要。

この仕組みは `work/20261102-pages-release-candidate`（PR #590）の内容を基点に、分離したPRでレビューする。レビューおよび必要な統合が終わるまで、`main`、Vercel、DNS、現在の試験公開を変えない。

## 動作条件

- **二重の有効化**：管理者が GitHub Actions のリポジトリ変数 `KAIGO_PAGES_BETA_APPROVED=true` を明示設定し、かつ `main` にある `.github/pages-beta-mode.txt` の内容が `beta` である場合だけ、対象ファイル更新で検査・Pages試験公開を行う。片方だけでは公開しない。
- PR の変更時にはPythonの軽量テスト・構文検査のみ行う。全件ビルド・公開用artifactのアップロード・デプロイは行わない。制度上の独立受入は公開判断時に別途行う。
- **初期設定は自動更新OFF**。このPRに設定ファイルを同梱せず、変数も設定しない。PR #590の独立受入後、保護設定・レビュー手順と検査を整えたうえで、別PRでモードファイルを追加し、別の管理操作で変数を有効にする。順序も含めた承認記録が必要。
- 不正な値はエラーとし、暗黙に公開しない。
- `README.md` や運用メモのみの変更では重いビルドを自動実行しない。対象は UI、法令・手引データ、生成コード、テスト、依存関係などに限定する。

## 公開前の必須検査

1. 公開元は実行イベントで特定された SHA。旧ベータの固定 SHA に戻らない。
2. 元の Next.js ビルドと制度データ・テストを通す。
3. 静的手引 39 サービス・585 章、国 Q&A 詳細 7,392 件以上、法令詳細 1,552 件以上を確認する。収録件数が変わる場合、最低件数と検証方法を再審査する。
4. ローカルリンク欠損・危険な URL・ルート直下リンクは0、従来 Vercel への参照は試験公開の既存上限内、容量は10億バイト未満。
5. 全 HTML に試験公開表示と `noindex` を保持。未審査の資料を正式公開であるかのように見せない。
6. 上記のいずれかが失敗したら Pages の artifact をアップロードしない。前回公開済みのページを維持する。

## 正式公開への移行

正式公開は既存 `.github/workflows/kaigo-pages-release.yml` の **独立した法令・公開範囲・動作・端末・安全性の受入**を引き続き要求する。
承認のないまま `noindex` を削除したり、試験公開フローを本番公開扱いにしたりしない。

試験公開の自動更新を後日有効化した場合、正式公開の切替時は必ず `.github/pages-beta-mode.txt` を削除し、試験公開による本番上書きを防止する。正式公開の継続自動更新は、その後、承認記録の扱いと合わせて別途設計する。

## 運用上の注意

- `main` にマージされる前の変更は、公開サイトには反映しない。
- 固定 SHA で稼働中の `kaigo-pages-public-beta-main.yml` は今回変更しない。
- `pages-beta-mode.txt` を消せば将来の試験公開を止められるが、**すでに公開されたページが自動的に非公開になるわけではない**。
- GitHub Pages ではサーバー側 API が動かないため、静的検索や画面機能の同等性確認を続ける。

## Actions の実行時間節約方針（2026-11-02）

- 通常 PR 更新では、`kaigo-pages-continuous-beta.yml` の `verify` ジョブで Python の検査・構文チェックのみを行う。Next.js 全体の `npm run build`、13,000ページ規模の静的生成、Pages artifact のアップロードは **PRでは行わない**。
- **二重条件を明示的に満たした場合に限り**、マージ後の `main` の当該SHAで全件ビルド・法令データ検証・静的出力監査を実施する。失敗時は現行公開を維持する。
- `verify-publication-readiness-integration.yml` は制度・公開範囲のデータ、関連スクリプトやテストの更新時に自動検証する。無関係な画面・文章だけの更新では起動しない。必要なら `workflow_dispatch` で手動実行する。
- `kaigo-issue569-browser-acceptance.yml` は実ブラウザ・印刷の検査を維持するが、同一PRに新しい変更が来た場合、旧コミットの実行を中止する。最終受入は最新SHAで完了させる。
- 既存の国資料の現行性監視は、確認した主要ジョブが**週1回**、短時間の実行であるため保持する。無効化で検出遅延を生むことは避ける。
- Vercelの毎日の条件付きデプロイは旧本番の維持に関係するため、Pages正式切替の受入前には変更しない。
- 時間削減量は計測前に断定しない。GitHub Actionsの経過時間と利用枠計上時間は別であり、実行履歴で比較する。
- PRで最終公開受入・法令上の検証が不要になったわけではない。公開判定に必要なCIと独立受入を別途確認する。

## 2026-11-04 担当C：重複起動削減と安全な運用

- この変更の実装ブランチは `work/20261104-kaigo-c-actions-budget`。PR #592の元HEADから派生させ、`main`と公開済みPagesは変更しない。
- `github-pages-feasibility.yml` の通常PRは、公開ルート・検索・公開ゲートの軽量Pythonテストのみを行う。従来の `npm run build` を含む全件計測は削除せず、Eが固定SHAに対して `workflow_dispatch` で1回だけ明示実行する。
- `verify-publication-readiness-integration.yml` では `scripts/prepare_github_pages_beta.py` の単独変更を公開資格データの更新と誤認して起動しない。法令データ・審査スクリプトなどへの反応は維持する。
- 上記の軽量PRと手動全件検査を同等の合格証拠として扱わない。CIの結果は実行したジョブと固定SHAごとに区別する。
- `main` のブランチ保護は2026-11-04のGitHubブランチ取得結果では無効。GitHub Appから詳細保護APIは403で確認できなかった。変数の二重ゲートも「workflowファイル自体を変更できる権限」を防ぐ代替にはならない。自動更新の有効化前に保護・必須レビュー・必要なステータスチェックを管理者が確認する。
- GitHub Actions変数を設定する操作とモードファイル追加は今回実行しない。現行の初期値はOFFのままとする。
- PR上の旧runを打ち消す条件はPRイベントに限定し、手動実行した独立監査は打ち消さない。正式公開ワークフローの独立承認条件は変更しない。
- `tests/test_github_pages_actions_safety.py` に、二重ゲート、PRからのデプロイ禁止、手動全件監査、独立承認ゲート保持の退行検査を追加した。実CI実行はEの統合後に集約する。
