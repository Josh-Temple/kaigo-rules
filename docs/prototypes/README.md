# 通所介護・サービス別手引のローカル試用

状態：**試用UI / 公開サイト未接続 / 制度解説の人手レビューは後続工程**（2026-10-13）。

## 使い方

1. `docs/prototypes/dayservice-handbook.html` を手元に保存してブラウザで開く。
2. 左側の15章から関心のある項目を選ぶ。リンクから既存の公開DBで関連資料を調べる。
3. 疑問・欠けている説明・照合すべき条項をメモし、JSONを書き出して保持する。

本HTMLは `app/`・`public/` の外に置き、サービス別ルート／API／検索結果／sitemap／公開allowlistを変更しない。
GitHub上のソースファイルは公開Repositoryの閲覧権限に従って見えるが、サービス利用者向けのサイトページではない。

## 信頼境界

- 15章の名称は既存の非公開 `39サービス × 15章` 構想に合わせる。ただし現時点で根拠付きの手引本文は **0件**。
- 章の短い説明は「何を調べるか」の案内に限定し、法令の解釈・算定可否・適用可否を断定しない。
- 公開DBへのリンクは検索／閲覧の入口であり、当該章の個別根拠の承認ではない。
- メモは個人の検討記録。 `review_completed:false` は固定し、端末内メモからcanonicalの人手レビュー状態・現行性・公開状態へ書き戻さない。
- localStorageは端末・ブラウザによって動作が異なる。記録の維持にはJSON書き出しを使う。個人情報・利用者情報・秘密情報を入力しない。
- 本番公開・マージ・DBの法令ステータス昇格・専門家レビュー済み表記は、このDraft PRの範囲外。

## 検査

```bash
python -m unittest discover -s tests -p 'test_dayservice_handbook_trial.py' -v
```

対象テストは15章ID、固定リンク、未確認の扱い、外部スクリプト不使用、メモと人手レビューの分離を確認する。ブラウザ実機試験と法令の正確性検証を代替しない。

## 次の実装単位

ユーザーの試用で必要な章・確認観点がまとまった後、公開DBのcanonical `service_id / source_family / source_id / version / record / locator` に結び付ける。信頼できるサーバー側の原典・公開ポリシーの確認と、必要なレビューなしに制度結論は表示しない。

この段階で39サービスへ本文を一括展開したり、レビュー未了を自動完了としたりしない。


## 原典候補の章別接続（第2段階・非公開）

GitHub `main@098a349c26f35cd9e9ad8f0b7ff54f2068f6a702` を入力snapshotとして、通所介護の既存データから **27個の章×項目候補** を取り込みました。内訳は基準省令7、解釈通知の章構造10、報酬告示の項目構造10で、15章のうち11章に候補があります。同一の報酬項目を複数の実務章から参照するため、27は固有法令数を意味しません。

- 基準省令：`data/rule-nodes.json` の固定レコードIDと原文、源資料ID、条・項・号をそのまま参照する。収載時の検証ラベルを表示するが、**手引の新しい人手確認ではない**。
- 解釈通知：`data/notice-current-skeleton.json` の番号・見出し・収載状態と、対応する出典候補（改正対照表・旧資料を含む）を案内する。未検証・「略」の箇所を現行確定原文へ昇格しない。
- 報酬告示：`data/remuneration-current-skeleton.json` の項目ID・見出し・原典位置を案内する。算定可否・単位数・加算適用の結論は表示しない。
- `data/sources.json` にある原典URLを利用する。閲覧者がリンクを押すまで外部通信はしない。リンク先の現在の到達性・法令有効性は本試作で保証しない。
- まだ個別候補を結び付けていない4章：指定・開設、届出・手続、国Q&A、原典・改正履歴。共通の公開DB検索入口は表示したままにする。**旧Q&A問50を現在有効なQ&Aとして表示しない**。

閲覧者は各候補を「未着手」「原典を開いた」「要再確認」の**個人用閲覧記録**としてマークでき、章ごとの自由メモとともにJSONで書き出せます。これらはすべて利用者のローカル作業メモであり、法令の検証台帳・human review・publication statusへ書き戻しません。機微情報を入力しないこと。

`tests/test_dayservice_handbook_trial.py` は各候補のID・原文・収載ラベル・原典URLを、Git Blob SHAを含めて固定source dataと突合します。source dataが変わったら自動的に検証が失敗し、候補一覧の再作成が必要になります。8つのテストメソッドを追加しており、UIの実機操作・個別法令の現在性や内容確認を検証するものではありません。
